# Assignments & Rubrics - Final Project Proposal

## Final Project Proposal Overview

Completion of an individual final project using spatial data and spatial methods is a course requirement. Students are welcome to talk through ideas with classmates and support one another, but each student must produce an individual proposal, an individual project, and an individual final submission.

The proposal is due in Week 04 and is meant to help students define a project that is manageable, personally meaningful, and fun. The emphasis is not on "saving the world" or designing an overly complex research agenda. The emphasis is on exploring the ideas and methods of the course in a way that feels exciting, useful, and possible within one quarter.

Good projects can be serious, playful, practical, artistic, experimental, or personal. Past examples might include mapping edible plants on campus and pairing them with recipes, geocoding song lyrics and building a browsable globe, exploring elephant movement trajectories, or using raster elevation data to create a 3D print model of favorite climbing routes. It is all fair game as long as the project is spatial and the student is genuinely having fun with it.

## What Students Should Submit

Submit both of the following:

1. A project proposal of no more than 1 page or about 500 words.
2. A polygon GeoJSON file representing the project's Area of Interest (AOI).

The proposal should include:

- A brief explanation of the project's goal and the central spatial question.
- A short overview of similar, relevant, or inspiring work.
- A very short bibliography.
- A simple proposed workflow or model.
- A description of the data needed and possible sources.

## File Naming Convention

Use the same file-naming logic introduced in the Week 01 GeoJSON.io assignment: start filenames with your SUNet ID, then identify the assignment, then identify the file type or deliverable.

For this assignment, use:

- `sunetid_final_project_proposal.pdf` or `sunetid_final_project_proposal.docx`
- `sunetid_final_project_proposal_aoi.geojson`

Replace `sunetid` with your actual Stanford SUNet ID.

Use this naming pattern moving forward for similar file submissions in this course, especially when submitting GeoJSON, shapefiles, maps, reports, and other exported project files.

## Proposal Emphasis

- Do not try to save the world with this assignment. Keep the scope controlled and make the project something you actually want to spend time on.
- Start with a maximum of 2 existing datasets. Students do not need to begin with any existing datasets at all, but if they do, the starting point should stay small and manageable.
- Have fun. The project is for exploring the methods and ideas of the course in a way that is personally meaningful.
- All final project submissions should use ArcGIS StoryMaps as the final presentation venue.

## Rubric

Total possible points: 10

| Criteria | What to look for | Points |
| --- | --- | ---: |
| Spatial question or idea | What is the "where" of the project, and why does it matter to the student? The proposal should present a clear spatial question or idea that is specific enough to be workable and interesting enough to sustain a quarter-long project. | 2 |
| Proposed workflow | The proposal describes a simple, understandable workflow. It does not need to sound highly technical, but it should make clear what the student plans to do with the data, methods, or tools. | 2 |
| Data sources | The proposal identifies likely data sources, ideally with links, and briefly explains why those sources are useful for the project. Students should begin with no more than 2 existing datasets unless they are primarily creating their own data. | 2 |
| Literature review / bibliography | The proposal includes a brief review of relevant prior work, examples, or inspirations, with a short bibliography. In most cases, 4 or fewer sources is appropriate for this proposal stage. | 2 |
| GeoJSON file of the AOI | Student submits a polygon GeoJSON file representing the project Area of Interest. The file should open correctly, match the proposed project area, and follow the required naming convention. | 2 |

## Grading Notes

- This rubric treats the proposal as an early design exercise, not a final research defense.
- Scope control matters. Smaller, clearer, more joyful proposals are usually stronger than ambitious proposals that depend on too many datasets, too many methods, or too many unknowns.
- A creative or unconventional project is completely acceptable if the student can explain the spatial question, likely workflow, and data needs.
- The final project itself should ultimately be submitted using ArcGIS StoryMaps, so proposals that already anticipate that format are on the right track.
- File naming matters because it keeps submissions organized and easier to review. Use the `sunetid_assignment_deliverable.ext` pattern consistently for similar files going forward.
